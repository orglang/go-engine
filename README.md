# OrgLang Engine

Рантайм исполнения OrgLang на Go.

## Структура

- `cmd/engine/` — точка входа и задачи сборки/запуска исполняемого приложения.
- `app/` — прикладные сценарии и входящие адаптеры (HTTP и другие интерфейсы); здесь нет `package main`.
- `adt/`, `pool/`, `proc/` — доменные возможности движка, сгруппированные по предметным областям.
- `lib/` — общие технические контракты и инфраструктурные компоненты, используемые ядром.
- `db/` — локальная инфраструктура БД, миграции и контейнерная конфигурация.
- `proto/` — протоколы и версии форматов/исполнения.
- `test/` — сквозные проверки, архитектурные проверки и тестовые сценарии.

`pkg/` предназначен для публичных переиспользуемых пакетов, если репозиторий действительно предоставляет такой Go API. Engine сейчас организован как приложение; его предметные пакеты не выделяются в публичный SDK только из-за наличия экспортируемых Go-идентификаторов, поэтому пустой `pkg/` не добавляем.

Зависимости направлены внутрь: доменные и прикладные пакеты не зависят от конкретных драйверов. Контракты размещаются рядом с кодом, который ими владеет; реализации — в adapter-пакетах на внешнем краю.

## Разработка

- `task sources:check` — генерация/проверка исходников и линтеры.
- `task tests:unit` — unit-тесты.
- `task tests:it` — интеграционные тесты.
- `task tests:e2e` — сквозные тесты.
- `task engine:binary` — сборка бинарника в `app/engine`.
- `task engine:process` — запуск приложения.

Инструменты разработки фиксируются отдельно в `gear.mod` / `gear.sum`; зависимости приложения — в `go.mod` / `go.sum`.
