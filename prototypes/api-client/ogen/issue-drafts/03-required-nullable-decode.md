# Bug: ogen v1.25.0 rejects explicit null for required nullable object properties

## Summary

ogen v1.25.0 generates a decoder that rejects an explicit JSON `null` for a property that is both required and nullable in an OpenAPI 3.1 schema.

Requiredness and nullability are independent:

- required means the JSON object must contain the property;
- nullable means the property's value may be `null`.

The expected behavior is to reject an omitted property while accepting an explicitly present property whose value is `null`.

## Minimal OpenAPI 3.1 reproduction

The repository fixture is `fixtures/required-nullable-cycle.yaml`. An equivalent minimal schema is:

```yaml
openapi: 3.1.0
info:
  title: Required nullable property
  version: 1.0.0
paths:
  /probe:
    get:
      operationId: probe
      responses:
        '200':
          description: OK
          content:
            application/json:
              schema:
                $ref: '#/components/schemas/B'
components:
  schemas:
    A:
      type: object
      required: [b]
      properties:
        b:
          $ref: '#/components/schemas/B'
    B:
      type: object
      required: [a]
      properties:
        a:
          anyOf:
            - $ref: '#/components/schemas/A'
            - type: 'null'
```

The TypeSpec reproduction is in `tsp/probes/required-nullable-cycle/main.tsp`; it emits the OpenAPI 3.1 schema at `probe-typespec-nullable/openapi.yaml`.

## Expected behavior

For the required nullable property `B.a`:

- `{}` must be rejected because the required property is absent;
- `{"a":null}` must be accepted because the property is present and nullable;
- `{"a":{"b":{"a":null}}}` must be accepted and decoded recursively.

## Actual behavior

The generated decoder rejects both explicit-null cases. The runtime error reports that it expected an object:

```text
decode B: callback: decode field "a": decode A:
"{" expected: unexpected byte 110 'n'
```

The missing-property case is rejected, as expected.

The reproduction test is `fixtures/required-nullable-runtime_test.go`.

## Baseline comparison

The same runtime test was run against clients generated by:

- unmodified ogen v1.25.0;
- the go-engine recursive-required-field prototype based on ogen v1.25.0.

Both generated clients fail the explicit-null and nested-object-with-null cases. Both reject the missing-property case.

Therefore, this behavior is present in the unmodified v1.25.0 baseline and is not a regression introduced by the recursive-required-field prototype.

## Scope and suspected area

This is a required/nullability decoding issue for OpenAPI 3.1 nullable unions represented as `anyOf: [object, null]`. The generated decoder appears to dispatch directly to the object decoder instead of accepting JSON `null` as the nullable alternative.

The fix should preserve the distinction between property presence and property value:

- absence must still fail required-field validation;
- explicit `null` must be accepted for nullable properties;
- explicit `null` must remain rejected for non-nullable properties.

This issue is independent of the generator's failure on required recursive object cycles. It should be investigated and fixed separately.
