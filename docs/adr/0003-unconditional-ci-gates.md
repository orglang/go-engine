# ADR-0003: Безусловный запуск CI gates

- **Статус:** Accepted
- **Дата:** 2026-11-20

## Контекст

CI stages организованы как цепочка зависимостей mise: `specs:gate` → `sources:gate` → `binaries:gate`. Downstream gate отвечает за запуск всей предшествующей цепочки.

Фильтрация через `mise run --affected` выбирает задачи по изменённым их собственным `sources`, а затем добавляет зависимости выбранных задач. Изменение входов dependency само по себе не выбирает её downstream dependents. Поэтому, например, изменение Go-файла может выбрать `sources:gate`, но не выбрать агрегирующий `binaries:gate`, который должен запускать полный pipeline.

Это создаёт риск, что обязательный CI check завершится без выполнения ожидаемой стадии.

## Решение

Не использовать `--affected` и changed-path filtering в GitHub Actions workflows репозитория.

Каждый запущенный workflow безусловно вызывает соответствующий gate или проверку. Полная последовательность стадий определяется зависимостями mise, а не повторной логикой определения изменённых файлов в GitHub Actions.

Условия жизненного цикла PR, например запуск отдельного workflow только для draft или только для Ready for review, сохраняются: они не являются фильтрацией по содержимому изменений.

## Последствия

### Положительные

- Изменения в любой части pipeline не могут случайно пропустить downstream gate из-за направления распространения affectedness.
- GitHub Actions не дублирует граф зависимостей и правила выбора задач mise.
- Required checks имеют предсказуемое поведение независимо от состава diff.

### Отрицательные

- На PR запускается больше проверок, в том числе не затронутых напрямую изменениями.
- CI может занимать больше времени и ресурсов.

## Когда пересмотреть решение

Вернуться к этому ADR следует, если появится единый и проверяемый механизм выбора стадий, который учитывает транзитивные зависимости и гарантирует запуск всех downstream gates, необходимых для затронутых входов.
